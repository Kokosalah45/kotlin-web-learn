# Basic Types

<DocSource docs={["types-overview"]} />

In Kotlin **everything is an object** in the sense that you can call members on any value —
`1.toString()`, `'a'.code`, `true.not()`. Numbers, characters and booleans still compile to
JVM primitives where they can, so the class-like surface costs nothing; but there is no
`int` versus `Integer` split in the language, and no implicit conversion between numeric
types either.

Outputs below come from running `examples/language-basics/basic-types.kt`.

## The seven families

| Category | Types | Holds |
| :--- | :--- | :--- |
| [Integers](/language-basics/basic-types/integers) | `Byte`, `Short`, `Int`, `Long` | whole numbers |
| [Unsigned integers](/language-basics/basic-types/unsigned-integers) | `UByte`, `UShort`, `UInt`, `ULong` | non-negative whole numbers |
| [Floating-point numbers](/language-basics/basic-types/floats) | `Float`, `Double` | numbers with a fractional part |
| [Booleans](/language-basics/basic-types/booleans) | `Boolean` | `true` and `false` |
| [Characters](/language-basics/basic-types/characters) | `Char` | one UTF-16 code unit |
| [Strings](/language-basics/basic-types/strings) | `String` | a sequence of characters |
| [Arrays](/language-basics/basic-types/arrays) | `Array<T>`, `IntArray` and friends | a fixed-size sequence |

```kotlin
val anInt: Int = 42
val aUInt: UInt = 42u
val aDouble: Double = 42.0
val aBoolean: Boolean = true
val aChar: Char = 'K'
val aString: String = "Kotlin"
val anArray: Array<Int> = arrayOf(1, 2, 3)

for (value in listOf<Any>(anInt, aUInt, aDouble, aBoolean, aChar, aString, anArray)) {
    println("${value::class.simpleName.toString().padEnd(10)} $value")
}
```

```text
Int        42
UInt       42
Double     42.0
Boolean    true
Char       K
String     Kotlin
Array      [Ljava.lang.Integer;@c818063
```

<Callout type="warning">
  The last line is the first array lesson: `Array.toString()` gives you a type tag and a
  hash code, not the contents. Use
  [`contentToString()`](/language-basics/basic-types/arrays) — and never `==` to compare
  arrays.
</Callout>

Sizes in bits:

```kotlin
println("Byte=${Byte.SIZE_BITS} Short=${Short.SIZE_BITS} Int=${Int.SIZE_BITS} Long=${Long.SIZE_BITS}")
println("Float=${Float.SIZE_BITS} Double=${Double.SIZE_BITS}")
println("UByte=${UByte.SIZE_BITS} UShort=${UShort.SIZE_BITS} UInt=${UInt.SIZE_BITS} ULong=${ULong.SIZE_BITS}")
```

```text
Byte=8 Short=16 Int=32 Long=64
Float=32 Double=64
UByte=8 UShort=16 UInt=32 ULong=64
```

## Everything is an object

```kotlin
println(1.toString())
println(1.plus(2))
println('a'.code)
println(true.not())
println(3.14.compareTo(2.71))
println(1 is Any)
```

```text
1
3
97
false
1
true
```

`1 + 2` *is* `1.plus(2)`; the operators are member functions, which is what makes
[operator overloading](/classes-and-objects/class-members/methods) work uniformly.

## What the JVM stores

A non-nullable `Int` is a JVM `int`. Make it nullable — or put it in a generic container —
and it becomes a boxed `java.lang.Integer`:

```kotlin
val plain: Int = 1
val nullable: Int? = 1
println(plain::class.java)
println(nullable!!::class.java)
println(plain::class.javaPrimitiveType)
println(plain::class.javaObjectType)
```

```text
int
class java.lang.Integer
int
class java.lang.Integer
```

<Callout type="info">
  This is the only place the primitive/wrapper distinction leaks into Kotlin, and it leaks
  as a **behaviour** change rather than a type change: boxed values can be compared with
  `===`, and the JVM caches small ones, so `===` on two `Int?` holding `100` is `true` while
  `10000` is `false`. Details under [Integers](/language-basics/basic-types/integers#boxing-and-the-jvms-small-integer-cache).
</Callout>

## Non-nullable by default

Every type excludes `null` until you add `?`:

```kotlin
val required: String = "present"
val optional: String? = null
println(required.length)
println(optional?.length)
println(optional is String)
println(null is String?)
```

```text
7
null
false
true
```

See [Null safety](/null-safety).

## Any, Unit and Nothing

Three types that are not "basic" but turn up constantly:

| Type | Values | Used for |
| :--- | :--- | :--- |
| `Any` | every non-null value | the root of the class hierarchy |
| `Unit` | exactly one, `Unit` | the return type of a function that returns nothing useful |
| `Nothing` | none | an expression that never produces a value |

```kotlin
val anything: Any = 1
println(anything)
println(Unit)
println(Unit::class.simpleName)
fun doNothing() {}
println(doNothing() === Unit)
fun stop(): Nothing = throw IllegalStateException("stopped")
println(runCatching { stop() }.exceptionOrNull()?.message)
println(emptyList<Nothing>())
```

```text
1
kotlin.Unit
Unit
true
stopped
[]
```

`Unit` prints as `kotlin.Unit` and really is a singleton object — see
[Standard functions](/functions/standard-functions#unit-is-a-real-type). `Nothing` is a
subtype of every type, which is what makes `throw` usable as an expression — see
[Exceptions](/control-flow/exceptions#the-nothing-type).

## No implicit numeric conversion

Numeric types are **not** subtypes of one another, so nothing widens silently on assignment
or at a call site. You convert explicitly:

```kotlin
val small: Int = 1
println(small.toDouble())
println(small.toLong())
```

```text
1.0
1
```

`val one: Double = 1` does not compile, and neither does passing an `Int` to a function
expecting a `Double`. Arithmetic *expressions* are the exception — there, the operators pick
a result type:

```kotlin
println((1 + 1L)::class.simpleName)
println((1 + 1.0)::class.simpleName)
println((1.0f + 1.0)::class.simpleName)
println(('a' + 1)::class.simpleName)
```

```text
Long
Double
Double
Char
```

<Callout type="warning">
  Two surprises hiding in that list. `Byte + Byte` is an **`Int`**, not a `Byte` — there is
  no `plus(Byte): Byte` overload — so `val b: Byte = b1 + b2` fails to compile. And
  `Char + Int` is a `Char`, so `'a' + 1` is `'b'` rather than `98`; use `.code` when you
  want the number.
</Callout>

## Non-denotable types

Some types exist only inside the compiler and cannot be written in source — you meet them
in error messages and IDE tooltips rather than in code: platform types (`String!`) from
[Java interop](/language-basics/introduction-to-kotlin/java-interoperability), intersection
types from [smart casts](/language-basics/data-types/type-checks-and-casts), integer literal
types from numeric inference, and captured types from generics.
