# List-specific Operations

<DocSource docs={["list-operations"]} api={["kotlin-stdlib/kotlin.collections/-list/"]} />

A `List` is ordered, so every element has a position — and that position is what the
list-specific operations are built on.

Outputs below come from running `examples/collection-operations/list-operations.kt`.

## Retrieve elements by index

`get(index)` and the `[index]` shorthand read an element. Out of bounds throws, so
`getOrNull()` and `getOrElse()` exist for the unsafe cases:

```kotlin
val numbers = listOf(1, 2, 3, 4)
println(numbers.get(0))
println(numbers[0])
println(numbers.getOrNull(5))
println(numbers.getOrElse(5) { it })
println(runCatching { numbers[5] }.exceptionOrNull()?.let { it::class.simpleName })
```

```text
1
1
null
5
ArrayIndexOutOfBoundsException
```

The thrown type is `ArrayIndexOutOfBoundsException` — a subclass of
`IndexOutOfBoundsException`, which is what you would catch. `getOrElse`'s lambda receives
the out-of-range index, which is why it printed `5`.

## Retrieve list parts

Beyond the common
[part-retrieval functions](/collection-operations/retrieving-collection-parts), lists have
`subList(from, to)`. It returns a **view**, not a copy:

```kotlin
val upTo13 = (0..13).toList()
println(upTo13.subList(3, 6))

val mutableSource = mutableListOf(0, 1, 2, 3, 4, 5)
val view = mutableSource.subList(1, 4)
println(view)
mutableSource[2] = 99
println("view after source change: $view")
```

```text
[3, 4, 5]
[1, 2, 3]
view after source change: [1, 99, 3]
```

<Callout type="warning">
  Changes flow both ways between a list and its `subList`. For an independent copy, use
  `slice()` or `toList()` on the result.
</Callout>

## Find element positions

### Linear search

`indexOf()` and `lastIndexOf()` return the first and last position of a matching element,
or `-1`:

```kotlin
val dupes = listOf(1, 2, 3, 4, 2, 5)
println(dupes.indexOf(2))
println(dupes.lastIndexOf(2))
println(dupes.indexOf(99))
```

```text
1
4
-1
```

`indexOfFirst { }` and `indexOfLast { }` do the same with a predicate:

```kotlin
val four = mutableListOf(1, 2, 3, 4)
println(four.indexOfFirst { it > 2 })
println(four.indexOfLast { it % 2 == 1 })
```

```text
2
2
```

### Binary search

`binarySearch()` is far faster than a linear scan but **requires the list to be sorted**
ascending by the order being searched. If the element is absent it returns
`(-insertionPoint - 1)`:

```kotlin
val words = mutableListOf("one", "two", "three", "four")
words.sort()
println(words)
println(words.binarySearch("two"))
println(words.binarySearch("z"))
println(words.binarySearch("two", 0, 2))
```

```text
[four, one, three, two]
3
-5
-3
```

`"z"` would be inserted at index 4, so the result is `-4 - 1 = -5`. Restricting the search
to `[0, 2)` cannot see index 3, so it reports where `"two"` would go in that range instead.

<Callout type="warning">
  On an unsorted list the result is **undefined** — not an error:

```kotlin
println(listOf(5, 1, 4, 2, 3).binarySearch(4))
```

```text
2
```

  That happens to be right here, by luck. It will not be in general. Sort first, every time.
</Callout>

If the elements are not `Comparable`, pass a `Comparator` — and sort by that same
comparator:

```kotlin
data class Product(val name: String, val price: Double)

val productList = listOf(
    Product("WebStorm", 49.0),
    Product("AppCode", 99.0),
    Product("DotTrace", 129.0),
    Product("ReSharper", 149.0)
)
println(productList.binarySearch(Product("AppCode", 99.0), compareBy<Product> { it.price }.thenBy { it.name }))

val colors = listOf("Blue", "green", "ORANGE", "Red", "yellow")
println(colors.binarySearch("RED", String.CASE_INSENSITIVE_ORDER))
```

```text
1
3
```

A *comparison* search drops the search value entirely and looks for where your function
returns zero:

```kotlin
fun priceComparison(product: Product, price: Double) = sign(product.price - price).toInt()

println(productList.binarySearch { priceComparison(it, 99.0) })
```

```text
1
```

## Write operations

On top of the [common write operations](/collection-operations/write-operations),
`MutableList` adds index-based ones.

`add()` and `addAll()` accept a position; everything after shifts right:

```kotlin
val adding = mutableListOf("one", "five", "six")
adding.add(1, "two")
adding.addAll(2, listOf("three", "four"))
println(adding)
```

```text
[one, two, three, four, five, six]
```

`set()` — or `[] =` — replaces in place without moving anything; `fill()` overwrites
everything:

```kotlin
val updating = mutableListOf("one", "five", "three")
updating[1] = "two"
println(updating)

val filling = mutableListOf(1, 2, 3, 4)
filling.fill(3)
println(filling)
```

```text
[one, two, three]
[3, 3, 3, 3]
```

`removeAt(index)` removes by position, and later indices shift down by one:

```kotlin
val removing = mutableListOf(1, 2, 3, 4, 3)
removing.removeAt(1)
println(removing)
```

```text
[1, 3, 4, 3]
```

## Sort in place

Mutable lists get in-place versions of the
[ordering functions](/collection-operations/ordering) — same names, minus the `ed`/`d`:

```kotlin
val sorting = mutableListOf("one", "two", "three", "four")

sorting.sort()
println("Sort into ascending: $sorting")
sorting.sortDescending()
println("Sort into descending: $sorting")
sorting.sortBy { it.length }
println("Sort into ascending by length: $sorting")
sorting.sortByDescending { it.last() }
println("Sort into descending by the last letter: $sorting")
sorting.sortWith(compareBy<String> { it.length }.thenBy { it })
println("Sort by Comparator: $sorting")
sorting.reverse()
println("Reverse: $sorting")
```

```text
Sort into ascending: [four, one, three, two]
Sort into descending: [two, three, one, four]
Sort into ascending by length: [two, one, four, three]
Sort into descending by the last letter: [four, two, one, three]
Sort by Comparator: [one, two, four, three]
Reverse: [three, four, two, one]
```

Each call mutates the same instance, so each line starts from the previous one's result.
`asReversed()` on a mutable list returns a mutable reversed **view** — writes through it
reach the original.
