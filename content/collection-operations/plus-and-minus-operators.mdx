# plus & minus Operators

<DocSource docs={["collection-plus-minus"]} />

`plus` (`+`) and `minus` (`-`) are defined on collections. The left operand is a
collection; the right can be a single element or another collection. **The result is always
a new read-only collection** — neither operator mutates the receiver.

Outputs below come from running `examples/collection-operations/plus-and-minus-operators.kt`.

```kotlin
val numbers = listOf("one", "two", "three", "four")

val plusList = numbers + "five"
val minusList = numbers - listOf("three", "four")
println(plusList)
println(minusList)
println(numbers)
```

```text
[one, two, three, four, five]
[one, two]
[one, two, three, four]
```

The third line is the point: `numbers` is unchanged.

## minus treats an element and a collection differently

This asymmetry is easy to miss and is spelled out in the docs: removing a single **element**
drops only its *first* occurrence, while removing a **collection** drops *all* occurrences
of its elements.

```kotlin
val repeated = listOf("a", "b", "a", "c", "a")
println(repeated - "a")
println(repeated - listOf("a"))
```

```text
[b, a, c, a]
[b, c]
```

Same letter, same collection — the only difference is whether the right operand is wrapped
in a list.

## The `+=` trap

`plusAssign` (`+=`) and `minusAssign` (`-=`) are also defined, and which one runs depends
on how the variable is declared. This is the single most confusing part of the operator set.

On a **`var` read-only** collection, `+=` is `plus` followed by a reassignment — you get a
brand new list and the variable is rebound:

```kotlin
var readOnly = listOf(1, 2)
val before = readOnly
readOnly += 3
println(readOnly)
println("same instance as before: ${before === readOnly}")
```

```text
[1, 2, 3]
same instance as before: false
```

On a **`val` mutable** collection, `+=` mutates in place — every other reference to that
list sees the change:

```kotlin
val mutable = mutableListOf(1, 2)
val alias = mutable
mutable += 3
println(mutable)
println("same instance as alias: ${alias === mutable}")
```

```text
[1, 2, 3]
same instance as alias: true
```

<Callout type="warning">
  Identical-looking lines, opposite semantics. `var` + read-only allocates a copy and
  rebinds; `val` + mutable mutates shared state. A `val` read-only list rejects `+=`
  outright — there is nothing to reassign and nothing to mutate.
</Callout>

| Declaration | `+=` does | Other references see it |
| :--- | :--- | :--- |
| `var list = listOf(…)` | `list = list + x` (new list) | no |
| `val list = mutableListOf(…)` | `list.add(x)` (in place) | yes |
| `var list = mutableListOf(…)` | `list.add(x)` (in place) | yes |
| `val list = listOf(…)` | does not compile | — |
