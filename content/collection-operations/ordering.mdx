# Ordering

<DocSource docs={["collection-ordering"]} api={["kotlin-stdlib/kotlin.comparisons/"]} />

Order matters: two lists with the same elements in a different order are **not** equal.
Kotlin defines order in two ways — *natural* order, from the `Comparable` interface, and
*custom* order, from a `Comparator`.

Outputs below come from running `examples/collection-operations/ordering.kt`.

## Natural order: Comparable

Natural order is what a type sorts by when nothing else is specified. Most built-ins have
one: numbers use numeric order, `Char` and `String` use
[lexicographical order](https://en.wikipedia.org/wiki/Lexicographical_order).

To give your own type a natural order, implement `Comparable` and its `compareTo()`. The
returned `Int` is read as:

| Return | Meaning |
| :--- | :--- |
| positive | the receiver is greater |
| negative | the receiver is less |
| `0` | the two are equal |

```kotlin
class Version(val major: Int, val minor: Int) : Comparable<Version> {
    override fun compareTo(other: Version): Int = when {
        this.major != other.major -> this.major compareTo other.major
        this.minor != other.minor -> this.minor compareTo other.minor
        else -> 0
    }
}

println(Version(1, 2) > Version(1, 3))
println(Version(2, 0) > Version(1, 5))
```

```text
false
true
```

Implementing `compareTo()` is what makes `>`, `<`, `>=` and `<=` work on the type — the
operators delegate to it.

## Custom order: Comparator

A `Comparator` orders instances however you like, including types that are not
`Comparable` at all:

```kotlin
val lengthComparator = Comparator { str1: String, str2: String -> str1.length - str2.length }
println(listOf("aaa", "bb", "c").sortedWith(lengthComparator))
println(listOf("aaa", "bb", "c").sortedWith(compareBy { it.length }))
```

```text
[c, bb, aaa]
[c, bb, aaa]
```

`compareBy { }` is the short form: give it a lambda producing a `Comparable` value and it
orders by that value's natural order. It is almost always the one to reach for.

### Multiple criteria

`thenBy()` adds a tie-breaker. Sorting by length, then alphabetically:

```kotlin
println(
    listOf("aaa", "bb", "c", "b", "a", "aa", "ccc")
        .sortedWith(compareBy<String> { it.length }.thenBy { it })
)
```

```text
[a, b, c, aa, bb, aaa, ccc]
```

`compareByDescending` and `thenByDescending` flip either level independently — here, oldest
first, then by name within the same age:

```kotlin
data class Person(val name: String, val age: Int)

val people = listOf(Person("Ada", 36), Person("Bob", 36), Person("Cy", 29), Person("Dee", 41))
println(people.sortedWith(compareByDescending<Person> { it.age }.thenBy { it.name }))
```

```text
[Person(name=Dee, age=41), Person(name=Ada, age=36), Person(name=Bob, age=36), Person(name=Cy, age=29)]
```

### Nulls

`nullsFirst()` and `nullsLast()` wrap a comparator so it can handle a nullable type:

```kotlin
val withNulls = listOf("bb", null, "a", null, "ccc")
println(withNulls.sortedWith(nullsFirst(compareBy { it?.length })))
println(withNulls.sortedWith(nullsLast(compareBy { it?.length })))
```

```text
[null, null, a, bb, ccc]
[a, bb, ccc, null, null]
```

## Sorting functions

The functions on this page all return a **new** collection. The in-place versions
(`sort()`, `sortBy()`, …) exist only on `MutableList` — see
[List-specific operations](/collection-operations/collection-specific-operations/list-operations).

```kotlin
val numbers = listOf("one", "two", "three", "four")
println("Sorted ascending: ${numbers.sorted()}")
println("Sorted descending: ${numbers.sortedDescending()}")
```

```text
Sorted ascending: [four, one, three, two]
Sorted descending: [two, three, one, four]
```

`sortedBy()` / `sortedByDescending()` take a selector; `sortedWith()` takes a `Comparator`:

```kotlin
println("Sorted by length ascending: ${numbers.sortedBy { it.length }}")
println("Sorted by the last letter descending: ${numbers.sortedByDescending { it.last() }}")
println("Sorted by length ascending: ${numbers.sortedWith(compareBy { it.length })}")
```

```text
Sorted by length ascending: [one, two, four, three]
Sorted by the last letter descending: [four, two, one, three]
Sorted by length ascending: [one, two, four, three]
```

<Callout type="info">
  Kotlin's naming rule shows up clearly here. **Past participle** (`sorted`, `reversed`,
  `shuffled`) returns a new collection; **imperative verb** (`sort`, `reverse`, `shuffle`)
  mutates in place and only exists on mutable types.

```kotlin
val original = listOf(3, 1, 2)
original.sorted()
println(original)
```

```text
[3, 1, 2]
```

  Calling `sorted()` and ignoring the result does nothing at all.
</Callout>

## Check sorted order

`isSorted()`, `isSortedDescending()`, `isSortedWith()`, `isSortedBy()` and
`isSortedByDescending()` test whether elements already follow an order. They return `true`
for fewer than two elements, and stop at the first out-of-order pair.

```kotlin
println(listOf(1, 2, 3, 4).isSorted())
println(listOf(4, 3, 2, 1).isSortedDescending())
println(people.isSortedBy(Person::age))
println(emptyList<Int>().isSorted())
println(listOf(1).isSorted())
```

```text
true
true
false
true
true
```

The docs call out three details: use these only on collections with a guaranteed iteration
order (a `HashSet` may answer differently between calls); `NaN` counts as greater than
everything and `-0.0` as less than `0.0`; and a `null` selector result sorts below any
non-null value. On a `Sequence` the call is **terminal** — it consumes the sequence.

## Reverse order

`reversed()` returns a copy. `asReversed()` returns a reversed **view** of the same
instance — cheaper, but it tracks the original:

```kotlin
val mutable = mutableListOf("one", "two", "three", "four")
val reversedView = mutable.asReversed()
val reversedCopy = mutable.reversed()
println(reversedView)
mutable.add("five")
println("view after add:  $reversedView")
println("copy after add:  $reversedCopy")
```

```text
[four, three, two, one]
view after add:  [five, four, three, two, one]
copy after add:  [four, three, two, one]
```

<Callout type="warning">
  The view changed when the source did; the copy did not. `asReversed()` is the lighter
  choice when the original will not change — and a liability when it might. If the
  mutability is unknown, or the source is not a list, prefer `reversed()`.
</Callout>

## Random order

`shuffled()` returns a new list in random order, optionally from a supplied `Random`:

```kotlin
println(numbers.shuffled())
```

Output varies per run, which is why this page does not pin one. Pass a seeded
`Random(seed)` when you need reproducibility.
