# Collection Operations

This is the largest section of the roadmap and the one you use every day. Every page here
is written against the official docs and every output shown was produced by running the
example file named on the page.

## Start here

[Operations Overview](/collection-operations/overview) explains how the whole API is laid
out: member vs extension functions, why results must be assigned, the `*To` destination
variants, and the naming rule that tells you whether a function mutates.

[Constructing Collections](/collection-operations/constructing-collections) covers making
one in the first place, and the difference between a copy and a second reference.

## Things that catch people out

Each of these is demonstrated with verified output on its page:

- [`associateBy` silently drops colliding keys](/collection-operations/transformations#associate) — use `groupBy` when keys repeat
- [`all {}` is `true` on an empty collection](/collection-operations/filtering#test-predicates)
- [`average()` on an empty collection is `NaN`](/collection-operations/aggregate-operations#the-basics)
- [`+=` means different things on `var` vs `val`](/collection-operations/plus-and-minus-operators#the--trap)
- [`- element` removes one occurrence, `- listOf(element)` removes all](/collection-operations/plus-and-minus-operators#minus-treats-an-element-and-a-collection-differently)
- [`takeWhile` stops early; `filter` does not](/collection-operations/retrieving-collection-parts#predicate-variants)
- [`fold` and `reduce` give different answers for the same lambda](/collection-operations/aggregate-operations#fold-and-reduce)
- [`asReversed()` and `subList()` are live views, not copies](/collection-operations/ordering#reverse-order)
- [`==` on arrays compares references, not contents](/collection-operations/equality-and-hashing#arrays-are-the-exception)
